# ADR 0063: Public guides have Spanish sources

- Status: Accepted
- Date: 2026-09-17
- Extends: ADR 0058, ADR 0062
- Supersedes: ADR 0062 only for its statement that Spanish remains an explicit English fallback

## Context

The public guides have English, German (ADR 0058) and French (ADR 0062)
source pages. The interface itself is translated into Spanish, but a Spanish
visitor who opened a guide still got the English body under a notice saying
so. That notice was the only part of `/documentation` left in the wrong
language for one of the four locales the service offers.

## Decision

**Every public guide has a Spanish source under `docs/es/<slug>.md`.** It is a
translation of the English source the generator selects for that slug, in the
formal register (`usted`) the Spanish catalogue uses for its instructions.

**The same guarantees as the German and French sources.** Every heading keeps
the English section anchor through an explicit `{#anchor}`, so a link or a
language switch lands on the same section; code blocks, commands and
configuration are copied verbatim from the English source; relative links
resolve to the same pages. The generated `release-schedule` table in
`README.md` is not copied, because nothing would keep a translated copy
current; the Spanish page points at the English one and the official
lifecycle page instead, as the German page does.

**One list of guide languages.** `GUIDE_LANGUAGES` in
`webapp/documentation.py` names the languages with their own sources. The
documentation generator, the `/documentation/{slug}` route and the search-index
builder all read it, so adding a language is one entry plus its sources.

**The English notice stays, for a language without sources.** With English,
German, French and Spanish covered, no current locale shows it. The template
condition is kept, generated from `GUIDE_LANGUAGES`, so a future interface
language falls back to English honestly rather than silently.

## Consequences

- Adding or removing a public guide now means updating four source sets
  together: English, German, French and Spanish.
- `tests/test_frontend_documentation.py` checks that every Spanish page
  renders with `lang="es"` and the same section anchors as English.
- The generated Spanish templates under `frontend/templates/docs/es/` and the
  Spanish search overlay are checked in and regenerated by the existing build
  scripts; CI's `--check` modes catch a stale copy.
- A change to an English guide leaves the Spanish page behind until somebody
  updates it, exactly as for German and French. The anchor test catches a new
  or renamed section; a reworded paragraph is not caught.

## Alternatives considered

- **Keep the English fallback for Spanish.** Honest, but it left one of four
  interface languages with English guides, and the notice itself was the most
  visible sign of it.
- **Translate the French sources into Spanish.** Closer languages, but the
  French pages still contain untranslated English passages; the English
  source is the authoritative one, so it is what Spanish is translated from.
- **Machine translation at request time.** It would need an external service
  or a model in the request path, which the self-hosted frontend deliberately
  has neither of, and its output could not be reviewed before it was served.
