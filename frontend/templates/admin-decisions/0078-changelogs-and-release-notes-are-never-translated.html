ADR 0078: Changelogs and release notes are never translated

Accepted

{{ t.html('admin.docs.source', file='adr/0078-changelogs-and-release-notes-are-never-translated.md') }} {{ t('admin.decisions.back') }}

  • Status: Accepted
  • Date: 2026-09-24
  • Extends: ADR 0048, ADR 0077

Context

CHANGELOG.md is where every change is written down as it is made, under ## [Unreleased]. scripts/release_notes.py turns that section into the released version's section, writes the same body to RELEASE.md, and the release workflow publishes it as the GitHub release (ADR 0048, ADR 0067). The operator area renders the latest ten released sections as its Releases tab, generated by scripts/build_frontend_documentation.py into frontend/templates/admin-docs/releases.html and indexed for the operator search.

The operator documents around that tab are gaining German, French and Spanish sources, and the web application's interface exists in four catalogues. A Releases tab rendered in English beside translated neighbours looks like the next page waiting for docs/<language>/operator/releases.md.

A changelog is a record, like a decision record (ADR 0077): each section is frozen once released, ### Security entries are matched one for one by the records in security/advisories/, and the exact wording is what a downstream packager, an advisory and a pull request quote. A translated changelog is a second account of what a release changed. It is written after the fact, can omit or soften an entry - a security fix above all - and nobody could say which text the release actually shipped with.

Decision

CHANGELOG.md and RELEASE.md exist in English only, and only once. There is no translated changelog or release-notes file, and no step of the release translates them: not scripts/release_notes.py, not the release workflow, not a translation service at build time or at runtime.

The GitHub release body is the English RELEASE.md, as ADR 0048 already has it write, in every case.

The operator area's Releases tab shows the English sections in every locale. releases.html stays a single generated template; build_frontend_documentation.py builds no per-language variant of it and reads no docs/<language>/operator/releases.md. Its title, description, the source notice and the surrounding navigation follow the request's locale through webapp/locales/ like the rest of the area; the release headings and entries do not.

Translation work never touches the changelog. TRANSLATING.md lists it as out of scope, and a locale key that restates a changelog entry is refused in review. A translated guide may still describe a feature a release added; it describes current behaviour, not what a release changed.

Consequences

A changelog entry is written once, in the pull request that makes the change, and needs no translation review before a release can ship. The security advisory check, the release notes and the Releases tab all read the same text, so they cannot disagree about what a release fixed.

Operator documents translated per language must leave releases out: a generator that renders every operator page in every language has to exclude it rather than expect a translated source.

Operators who do not read English read the release notes in English or with their own tools. The guides that tell them what to do remain translated under ADR 0058, ADR 0062 and ADR 0063.

Alternatives considered

Translated release notes written at release time. Rejected: they would hold up every release on translation review, and a mistake in one could not be corrected without editing a released section.

Machine translation of the Releases tab when it is displayed. Rejected for the reasons ADR 0058 gives for the guides - a network or model dependency, and text that varies between visits - and because a security entry must say the same thing to every reader.

Translated section headings only (### Fixed, ### Security). Rejected: the headings are part of the record that scripts/release_notes.py and scripts/security_advisories.py parse, and a second spelling is a second format to keep them in step with.
